## Why run 1 failed

`reproduce.py`'s docstring says "The deterministic backend is reproducible, so
every headline number in the cited run's claims.json must come back identical."
The grading is deterministic. The proposal path is not, because it reads
wall-clock timings.

- `rde/behavior.py` defines behavioural novelty as a ratio of per-workload wall-clock times.
- `rde/engine.py:219` marks a candidate "stale" when its similarity to a prior candidate is at least `behavioral_similarity = 0.93` (`rde/config.py:101`). That is the same as novelty at or below 0.07.
- A stale round pushes the Synthesizer from CONTINUE to EXPLORE. That changes which candidates are proposed next, and so which points end up on the frontier.

At iteration 3, each run measured this novelty for its candidate:

| Run | it3 behavioural novelty | stale? | it3 action |
|---|---|---|---|
| cited (2026-06-10) | 0.0441 | yes | explore |
| run 1 (failed) | 0.0994 | no | continue, so the path diverged |
| run 2 | 0.0614 | yes | explore |
| run 3 | 0.0610 | yes | explore |
| run 4 (3.11) | 0.0642 | yes | explore |

The passing runs on this VM landed only 0.006 to 0.009 below the 0.07 cut-off.
Run 1 was the first heavy job on a freshly started container. No other work of
mine was running, but I cannot rule out container start-up activity. The
verdict fields (the utility maps, n_graded, robust_beats, the holdout verdict)
were identical even in the failed run. Only the two frontier fields moved.

`docs/V11_NOTES.md` (lines 177 to 184) already records that the proposal path
is "load-sensitive" and that acceptance "requires an UNLOADED machine". The
README and `reproduce.py` do not pass that caveat on. Run 1 suggests the
condition is about timing in general, not only about heavy load.

## README gaps a stranger would hit

1. **`reproduce.py` can fail on a correct checkout.** One of four runs on this VM exited 1 with 2 differences. The README presents `REPRODUCED: 24/24` as the guaranteed output and does not mention that the result depends on timing. A stranger who gets exit 1 will reasonably conclude the claim did not reproduce. The cause is the 0.07 novelty threshold described above.
2. **The time estimates are about half the real cost.**
   - `reproduce.py`: README ~3 min; 5 min 14 s to 5 min 35 s here; 3 min 32 s on the repo's own CI.
   - pytest: README ~15 min; 30 min 52 s here; 26 min 31 s on the repo's own CI.
   - The "Five minutes" section took about 5 min 37 s here.
3. **`pip install pytest` may be refused elsewhere (not hit on this VM).** It worked here because the container runs as root and its python3 (3.13) has no `EXTERNALLY-MANAGED` marker. A stranger using a stock Debian or Ubuntu system Python as a normal user can get pip's `externally-managed-environment` refusal. The README gives no venv alternative.
4. **The `python` command may not exist elsewhere (not hit on this VM).** The README calls `python` throughout. This VM has `/usr/bin/python`. A stock Ubuntu 24.04 install has only `python3` unless `python-is-python3` is installed.
5. **`check_claims.py` checks less than the README implies.** It checks three strings: the run id, the text `2 beats, 6 matches, 6 below`, and `beats_human`. The README's other numbers (n_graded=14, factor 1.95, +0.0126, +0.035/+0.059, −0.171/−0.137) are not machine-checked. I checked them by hand, and they all match the cited `claims.json`. Pointing `check_claims.py` at your own fresh run always fails with "README does not cite run id", so it cannot check a stranger's run.
6. **The "Python 3.11+" claim is only partly covered.** CI tests only 3.13. Here, 3.11 ran the toy demo and `reproduce.py` successfully, but I did not run the test suite on 3.11 or try 3.12.
7. **The toy demo's winner depends on timing.** This is a small point, not a defect. On 3.13 the synthesised hybrid won (fitness 0.753). On 3.11 the heap stayed best (0.733, synthesis gain 0.45). The README only promises "disqualify, synthesize, accept", and both runs did all three.
8. **The sequencing note is stale.** The README's "v11 sequencing" paragraph ends with "→ this commit (Half C ...)". Half C is `8e588e9`, and HEAD is three commits later (`e0b4203`).
9. **The live LLM path was not checked.** It needs a paid OpenRouter key. Without one it exits 2 with a clear message pointing to `.env.example` and `--backend deterministic`.
